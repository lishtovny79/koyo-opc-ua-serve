# Диагностика неисправностей

[English version](en/troubleshooting.md)

| Симптом | Что проверить |
| --- | --- |
| Значения PLC не обновляются | IP PLC, UDP-порт 28784, маршрутизацию, firewall и настройки Ethernet-интерфейса контроллера. |
| OPC UA-клиент не подключается | TCP-порт 4840, firewall хоста и настроенный endpoint. |
| Теги отсутствуют | Колонки CSV, поддерживаемую нотацию адресов и лог старта сервера. |
| Новый тег не появился | `Objects/ServerStatus/LastTagOperation`: там указана ошибка проверки или подтверждение добавления. |
| Нужен backup тегов | Вызовите `Objects/TagManagement/BackupTags`; файл появится в `plc.backup_directory`. |
| Запись не работает | `Client Access`, тип данных, режим PLC и логи сервера. |
| `AddTag`/`BackupTags` используют старый код | Пересоберите Docker-образ без кэша по инструкции в [установке](installation.md). |

При потере связи сервер оставляет последние значения в кэше.
`Objects/ServerStatus/PlcOnline` показывает успешность последнего обмена с PLC.
Пока он имеет значение `false`, считайте значения устаревшими.

## Отклонённые UDP-ответы

Сообщение `Rejected PLC UDP response: ...` указывает на неверного отправителя,
идентификатор транзакции, заголовок HAP, длину, CRC, фазу ответа, статус или размер
блока чтения. Такие пакеты пропускаются в пределах таймаута. Чтобы не переполнять
журнал, записываются первое и каждое сотое отклонение каждого вида.

Каждый запрос чтения получает новый двухбайтный идентификатор. После неудачного
обмена UDP-сокет заменяется, чтобы задержанный ответ на старый порт не попал в
следующий запрос. Кэш обновляется только после полного успешного цикла опроса.
При сбое блока сохраняется прежний кэш, публикация пропускается, а `PlcOnline`
становится `false`. Старые значения нельзя считать текущими.

При неверном размере ответа проверьте другие клиенты PLC, задержки сети и
`read_block_words`: блок не должен превышать фактический предел ответа PLC.
Эта проверка сама по себе не доказывает причину ранее полученного неверного значения.

## Некорректное значение BCD

`PLC decode failed: tag=... word=... raw=... next_word=...` содержит имя тега,
десятичный адрес слова и исходные значения перед повторным возбуждением ошибки.
Например, восьмеричный адрес V56 соответствует слову 46. В BCD допустимы только
цифры 0–9; полубайт A–F не является BCD-цифрой. Сверьте адрес и тип с программой
PLC. Диагностика не меняет тип тега и не подставляет выдуманное значение:
реальная ошибка декодирования по-прежнему останавливает сервер.
